# 提示词读取分工（唯一口径）

一段文字里可能同时有剧情、角色、场景、镜头、素材要求和对白。**每一次读取只允许做一件事**，
否则同一条信息会被两处用不同方式改写，最后谁也说不清哪个才是准的。

## 四条硬规则

1. **不改造原文**：需要「整理」时只切分、排序、去重；改写只发生在「润色」这一个入口。
2. **缺失就留空**：原文没写的景别、机位、音色、时长，一律给空值，由界面显示「未指定」。
   禁止用常识补全——补出来的东西用户不会逐条检查。
3. **输出必须是固定结构**：JSON 或固定字段；解析失败按失败处理，不做「尽力猜」。
4. **越权即失败**：某个入口返回了不属于它的字段（例如分镜拆分顺手写了音色描述），视为不合格。

## 各入口的职责

| 入口 | 输入 | 只做 | 明确不做 |
|---|---|---|---|
| 素材清单（剧本库） | 剧本正文 | 抽角色/场景/道具/配乐；角色写了声线才派生音色 | 不写景别、机位、运镜；不拆台词行；不排时长 |
| 分镜拆分（项目第三步） | 任意一段文字 | 按叙事顺序切成镜头；保留原文措辞；只在原文写了时填景别/机位/地点/表演/服装 | 不改剧情、不补人物、不润色、不把对白抽走 |
| 提示词润色 | 一条提示词 | 顺语序、补上能拍的细节（景别、机位、光线、材质） | 不换人物、不增删情节、不编身体细节 |
| 中译英 | 一条中文提示词 | 1:1 翻译 | 不解释、不扩写、不加风格词 |
| 图片描述（识图） | 一张图 | 只写看得见的事实：人物、服装、构图、光线 | 不猜身份、不写剧情、不评价画质 |
| 参考图描述 | 一张参考图 | 只提取人物与构图 | 不写光线、色调、材质、渲染风格 |
| 镜头语言拆解（参考视频） | 一段视频/说明 | 景别、机位、运动、节奏 | 不复制原片剧情、不生成新角色 |

## 冲突时谁说了算

- **原文 > 任何模型的补全**：用户写了的，模型只能整理，不能改写。
- **专门入口 > 顺手填写**：音色只由素材清单派生，分镜拆分里不许出现 voice 字段。
- **用户手改 > 模型建议**：清单/分镜一旦被用户改过，后续生成直接用手改后的值，
  模型再跑一次只是「重新建议」，不能覆盖未保存的修改。

## 改动的规矩

改任何一个 system prompt，必须同时：
1. 更新本表的「只做 / 不做」两列；
2. 在 `tests/` 里补一条「不该出现的字段没有出现」的断言；
3. 若是新增入口，先在这里加一行，再写代码。
