# 简化生成入口接入

关联需求：GitHub #12（普通创作免选技术工作流）；候选浏览延续 #7 的现有版本能力。

## 用户流程

正式 App 默认展示四个入口：文生图、文生视频、图生视频、图像／视频清晰化。没有作品时，选择入口会在本人账号下创建“快速草稿”；已有作品时沿用当前作品。无需先填写系列或作品名。草稿创建响应丢失时，按唯一标题查询本人项目列表，不盲目重复创建。

- 文生图：填写完整提示词和画幅，使用原 `KeyframePanel` 与 `keyframe-tasks`。结果登记到原素材库，可采用、下载、载入该图片的原提示词后再生成，或用作视频开始画面。
- 文生视频：只需提示词、画幅和时长。提交时不带入其他草稿的首尾帧和音频，由原自动解析器选择已存在的文本视频模板。
- 图生视频：上传或选择原素材库的开始画面，填写提示词并生成。上传仍使用原项目上传接口，生成仍使用原分镜计划、预检与任务接口。
- 生成方案：普通创作默认使用标准方案；16:9 且没有结束帧或表演声音时，可以明确选择“快速预览 · 已验证 8 步 + Kitchen”。纯文本使用 v4 LoRA、Euler/beta、8 步、Sigma shift 12/5 和 Kitchen attention；首帧视频使用已验证的 0.4MP 8 步 + Kitchen。切换为 1:1、9:16、结束画面或表演声音时自动回到标准方案。
- 图像／视频清晰化：从当前作品候选、历史成功输出或上传素材开始，使用 RealESRGAN 2×；原素材和新候选分别保留，不要求先采用，也不会自动替换分镜或成片。
- 修改：直接编辑当前分镜的完整提示词，保存后沿原任务入口再次生成。旧任务保留冻结输入。提交结果不明时沿用原凭据核对；不会把新提示词覆盖到旧请求。
- 结果：复用原片段列表、播放器、前后切换、历史版本和审核记录。此轮不新增比较系统；历史候选可查看原提示词与素材、恢复为当前后继续编辑。既有“当前版本”行为保留，采用仍需明确操作。
- 下载当前原始图片或视频；长作品装配和导出仍在完整工作台中。

“作品、片段与更多功能”打开原工作台。账户、权限、存储根、队列、模型和工作流契约不变。原 `prototype.html` 仍是独立的模拟交互记录，正式实现不依赖它的内存状态或模拟结果。

## 实现范围

- `src/App.tsx`：简化入口、延后命名、复用原创建/上传/预检/提交/审核与浏览方法。
- `src/KeyframePanel.tsx`：展开式入口、画幅、原候选提示词载入、完成后定位原素材。
- `src/quick-create.css`：限定于快速入口的布局，保留现有组件与全局样式。
- `vite.config.ts`：开发代理补充 `/openapi.json`，供原任务提交契约检查使用。
- `tests/quick_generation.browser.mjs` 与 `tests/quick_generation_bridge.py`：完整 React App、真实登录 Cookie 和隔离 ASGI 业务接口；GPU 调度替身和合成媒体仅用于自动测试。
- `tests/creation_assistant.browser.mjs`：刷新后通过公开按钮切回完整工作台，继续验证原助手的页面呈现、回执与跨标签页行为。
- 仓库根 `.gitignore`：新增源文件逐项列入公开白名单；测试产物和实际生成素材不纳入。

初次三入口接入未新增依赖、后端接口、数据库、任务模型或独立版本存储。下面的正式发布增量为原请求补充可选输出尺寸字段，仍沿用原任务与历史，不新增数据库表。

## 第一阶段候选状态整理（2026-10-13）

快速入口在结果区统一显示当前候选版本、审核状态、输出规格、处理方式和输入快照状态。原生生成显示为“原生生成”；2K / 4K / 8K 显示为“尺寸放大（Lanczos）”，若任务回执包含原生文件引用，页面会明确提示原生文件仍被保留。图片入口沿用关键帧任务回执中的处理档案，视频历史版本接口也返回相同的 `processing` 信息，便于后续追加独立 AI 高清候选。

失败任务的快速入口操作按状态分为“核对原任务结果”和“按原快照重试任务”，避免把未知回执和确定失败混成一次重试。任务、候选、提示词和审核记录仍使用原有接口与数据，不新增数据表。

## AI 高清候选真实验收（2026-10-13）

在正式工作台中对一个已采用的样片提交独立 AI 高清任务。任务通过现有 GPU 调度和 ComfyUI API 图执行，原候选保留为 A，结果登记为同一分镜的 B 候选并进入待审核状态。真实回执测得 1728 × 960、107 帧、24 fps、4.458 秒，并保留 1 条音轨；版本历史、候选清单和导出清单均能读取该 B 候选。高清结果不会自动采用，仍需人工比较后再提交审核。

首次联调发现 ComfyUI 输入根必须与 `storage.json` 的有效输入根一致；修正服务启动参数后重试成功。失败任务和成功任务都保留在原任务记录中，没有覆盖原片或重复采用。

## 文生视频清晰度复核（2026-10-15）

早期文生视频样片使用约 0.4MP 横屏画布（864×480）和 Turbo 采样，画面发糊主要发生在原生生成阶段；把成片放大到 2K/4K/8K 只能改变输出尺寸，不能补回采样时没有生成的细节。工作流已为纯文生视频单独切换到约 0.98MP 画布和标准 20 步采样，图生视频与外部音频引导方案继续使用原有快速档。

本机 RTX 5070 Ti 真实小样已通过正式工作台执行：5 秒横屏文生视频实际输出 `1344×768`、24 fps、124 帧、约 5.167 秒，码率约 2.6 Mbps；草地纹理和远景边缘较旧 864×480 样片明显清晰。该质量档的代价是本机 5 秒样片约耗时 11 分钟，不能把它当作实时预览。后续适合在界面上明确区分“快速草稿”和“清晰生成”，先用快速档确认构图，再对选中的提示词提交质量档。

## 已验证加速方案接入普通入口（2026-10-15）

普通创作现在可以显式选择“快速预览”，标准方案仍是默认值。后端新增两个只读可检查的 H3 配方：`h3-text-fast-v4-kitchen`（纯文本、16:9、约 0.98MP）和 `h3-first-fast-kitchen`（首帧、16:9、0.4MP）。两者均使用 8 步与 Kitchen attention；文生方案额外使用 v4 LoRA、Euler/beta 和 video/audio Sigma shift 12/5。模型文件沿用已经安装并实测过的本机文件，不自动下载。

通过正式工作台在独立验收作品中提交了真实文生加速任务并成功。实际冻结回执确认 `preset_id=h3-text-fast-v4-kitchen`、`speed_profile=fast`，ComfyUI 执行 256.288 秒，输出 1344×768、124 帧、5.167 秒、1 条音轨；页面预览 readyState 4，无错误，原 S01 版本保留为历史候选，未自动采用。此前独立基准的同配方多场景约 161–175 秒；这次耗时受当前运行状态和模型加载影响，只作为本机本次实测。

自动回退规则已经写入普通入口：快速配置只允许 16:9、单段、无结束画面和无表演声音；改变为其他画幅或附加控制会回到标准方案。标准和加速候选共用原有任务、历史、审核与下载链路，不覆盖旧作品。
