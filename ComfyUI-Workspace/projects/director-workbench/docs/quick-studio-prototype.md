# 轻创作交互原型 · 2026-10-10

本轮实现用户认可的最短路径：选择模板 → 放入素材 → 生成 → 修改提示词再生成 → 比较采用 → 导出。单张图片和单个片段可直接开始；整理为作品及归入系列是可选的后续操作。

## 打开与运行

在 `ComfyUI-Workspace/projects/director-workbench` 目录执行：

```powershell
node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 4188 --strictPort
```

打开 <http://127.0.0.1:4188/prototype.html>。原型使用独立 HTML 入口，不经过正式登录页，不请求业务 API，也不接入 ComfyUI。现有 `main.tsx`、全局样式和服务配置没有改动。

建议体验：

1. 选择“让图片动起来”，上传图片或点击“用示例体验”。
2. 输入描述，生成第一版，可以先采用。
3. 点击“修改提示词”，编辑当前候选的完整提示词，再点“用新提示词生成”。原有素材和规格沿用所选候选。
4. 新生成 V3 默认比较 V2 / V3，不因 V1 已采用而固定比较 V1；可以用左右选择器指定任意两个不同版本。左右提示词分别可展开，采用操作明确标出对应侧和版本。点击历史版本只改变预览。
5. 点击“接下一段”，生成并采用第二段；展开各段输入查看提示词和首尾帧。
6. 连续预演、导出；需要命名时点击“整理为作品”。

文生图仅需文字；首尾帧视频需两张图片。产物按顺序排列，不提供节点连线。下一段沿用上一段已采用版本的尾帧（若有）或示例画面，这只是交互演示，不是视频尾帧提取。

## 与现有工作台的关系

“片段浏览”仅验证已有能力的展示方式，不规划第二套故事编排模块。现有 `src/App.tsx` 已有分镜列表、`choose` 切换、前后片段按钮和播放控制，`ShotPromptEditor.tsx` 已有提示词编辑入口。后续正式接入应复用这些组件/状态与现有任务、候选、采用机制，重点优化当前片段的输入展示和操作路径。此次未修改正式 `App.tsx`。

修改采用“完整提示词 → 重新生成”的明确契约，不采集独立修改意见，不假设存在自动将意见转换为模型指令的能力。每个候选冻结实际提示词；从历史候选编辑时载入该候选的输入。

## 演示边界

- 生成使用内置原创 SVG 插画或上传图片，延时模拟任务完成；没有模型请求、真实图像编辑或视频生成。
- 修改后的完整提示词进入新候选快照，以示例色调变化演示比较；尚未连接真实模型，示例画面不代表提示词实际生成效果。
- 动态预演为浏览器图片缩放；连续预演按各段候选时长顺序切换。
- 导出实际下载自包含 HTML 演示预览，包含采用的画面、完整提示词及所基于的版本，不冒充 PNG/MP4 媒体产物。
- 数据仅在当前页面内存中；刷新或切换到其他模板会重置本次尝试。上传文件不离开浏览器。
- 可选归档仅改变演示标题，不创建账号、作品目录或数据库记录。

### 同日用户反馈修订与复测

- 修复前在浏览器复现：采用 V1 后生成 V2、V3，界面仍显示 V1 / V3。原因是对照优先取采用版本，否则取数组第一个不同版本。
- 修复后实测：V3 默认比较 V2 / V3，V4 默认比较 V3 / V4；采用状态不会影响默认对照。手动比较 V1 / V2、左右分别采用、禁止两侧选择同一版本均通过。
- 完整提示词编辑实测：从 V1、V2 打开编辑分别预填对应提示词，空白内容禁止生成；新 V3、V4 分别保留改后的完整提示词，旧 V1、V2 的提示词不变。
- 导出实测：查看 V4、采用 V3 时，下载文件包含 V3 的完整提示词，不混入 V4 草稿。
- 前后片段按钮、首尾边界禁用、切换片段后候选隔离和比较状态恢复通过。正式工作台原有浏览与播放逻辑未修改。
- 1440×1100 桌面与 390×844 手机比较视图检查通过；手机页面宽度 390，浏览器 0 errors / 0 warnings。
- 此次修订实际涉及 `src/QuickStudioPrototype.tsx`、`src/quick-studio-prototype.css`、本说明三个文件。
